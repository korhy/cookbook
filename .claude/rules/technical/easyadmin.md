# EasyAdmin 4

The back-office at `/admin` is **the only way content is edited** — the REST API is read-only. Every
authoring feature therefore lands here, not in a new endpoint.

## Dashboard

`src/Controller/Admin/DashboardController.php` carries
`#[AdminDashboard(routePath: '/admin', routeName: 'app_dashboard')]`. Its `index()` redirects
straight to the Recipe CRUD — the dashboard is a router, not a landing page.

`configureMenuItems()` is the navigation. **A new CRUD controller is invisible until it is added
there** — that is the single most common omission when adding an entity:

```php
yield MenuItem::linkToCrud('Recipe', 'fas fa-utensils', Recipe::class);
```

Icons are Font Awesome classes; keep the `fas fa-…` family already in use.

Admin assets come from AssetMapper via `Assets::new()->addAssetMapperEntry('admin')`. There is no
npm build step in this project — see the Assets section of `CLAUDE.md`.

## CRUD controllers

One controller per entity in `src/Controller/Admin/`, extending `AbstractCrudController`:

- `getEntityFqcn()` returns the entity class.
- `configureFields()` declares the fields. Prefer the typed field classes
  (`TextField`, `SlugField`, `AssociationField`, `CollectionField`) over `Field::new()`.
- `configureCrud()` / `configureActions()` for labels, sorting, and which actions exist.

**These controllers are configuration, not logic.** Business rules belong in a service, a validator
or a listener — see [backend-php.md](backend-php.md). If a CRUD controller starts computing
something, that computation is in the wrong place.

## Fields with a domain rule behind them

- **Slugs** are generated by `SlugListener`. Do not offer a free-text slug field that lets an
  editor break the invariant; if the slug is editable, it must still go through `SluggerService`.
- **`RecipeIngredient`** is a join entity with `quantity` + `unit`, so ingredients are edited
  through `CollectionField` over `RecipeIngredientType`, never an `AssociationField` straight to
  `Ingredient`. `IngredientAutocompleteField` (Symfony UX Autocomplete) is what keeps that usable
  against a large ingredient table.
- **`Instruction`** is ordered by `position`. Any editing UI must preserve or renumber `position`
  coherently — steps rendered out of order is a data bug, not a display bug.
- **Thumbnails** go through VichUploader (`recipe_thumbnail` mapping) on the non-persisted
  `thumbnailFile` property. Never write to `thumbnail` (the filename) by hand.

## Templates

Overrides live in `templates/admin/`. Override a single block rather than copying a whole EasyAdmin
template — a full copy silently stops receiving upstream fixes on the next bundle update.
